# 書き出し：ライブラリ全体を、フォルダ構成どおりに

ライブラリの中は `images/<id>/<元のファイル名>` で、アプリで付けた名前もフォルダ分けもディスクには表れない。
アプリの中では困らないが、バックアップや持ち出しのときに中身が分からない。

保存の形は今のまま（取り込むときにコピーし、`<id>` のフォルダに置く）にして、**書き出し** でアプリのフォルダ構成どおりの写しを作れるようにする。
2 回目からは変わったものだけを書き出し、タグ・評価・メモも一覧のファイルで残す。

## 決めたこと

| 論点 | 決定 |
|---|---|
| 保存の形 | 変えない。フォルダ構成どおりに保存する案と、元の場所のまま参照する案は採らない（下の「採らなかった案」） |
| 入口 | メニュー「ファイル」の「書き出し…」の次に「ライブラリ全体を書き出し…」。設定の「概要」にも同じ操作のボタン |
| 書き出し先の構成 | `<ライブラリ名>/<モード>/<フォルダ>/…/<名前>.<拡張子>`。未分類はモードのフォルダの直下 |
| 対象 | ゴミ箱以外のすべての項目（すべてのモード） |
| 2 回目以降 | 前回の記録（`.stockroom-export.json`）と比べ、新しいもの・変わったものだけを書く。アプリで移動・名前を変えたものは、書き出し先でも移す |
| ライブラリから無くなったもの | 既定では消さない。オプションで、書き出したときのままのファイルだけを消せる |
| 書き出し先で利用者が変えたファイル | 触らない。結果に件数を出す |
| タグ・評価・メモ | `stockroom.csv`（UTF-8・BOM 付き）に毎回すべて書き直す。既定でオン |
| 正式なバックアップ | これまでどおり `.library` フォルダのコピー（docs/FEATURES.md「バックアップ」）。この書き出しは「読める写し」で、ここからライブラリには戻せない |

## 書き出し先の構成

```
書き出し先/
  MyPictures/                      ← ライブラリ名。1 回目に作る
    .stockroom-export.json         ← 前回の記録（差分に使う）
    stockroom.csv                  ← タグ・評価・メモなどの一覧
    ストック/
      旅行/2025/京都/金閣寺.jpg
      旅行/2025/京都/金閣寺 (2).jpg
      請求書.pdf                    ← 未分類はモードのフォルダの直下
    フォント/
      欧文/Inter-Regular.ttf
```

- **項目が入るフォルダは 1 つ**（`item_folders` の `idx_item_folders_item`、`db.rs` の移行 step 5）なので、書き出す場所も 1 つに決まる。
  フォルダをまたぐまとまり（タグ）は、フォルダにはせず `stockroom.csv` に書く
- モードのフォルダ名は表示名（`MODES` の label：「ストック」「フォント」）。使っていないモードのフォルダは作らない
- ファイル名はアプリでの名前（`item.name`）に拡張子を付けたもの。使えない文字の置き換え・同じ名前の連番は今の書き出しと同じ（`export_target` / `safe_name`）
- フォルダ名も同じく置き換える。同じ親の下に同じ名前のフォルダが 2 つあると、ディスクでは 1 つにまとまる（中の同じ名前のファイルには連番が付く）
- 書き出し先に選んだフォルダに `.stockroom-export.json` があれば、そのフォルダを更新する。無ければ、その中に `<ライブラリ名>/` を作る
  （すでにあって記録が無ければ `<ライブラリ名> (2)/`）。書き出し先はライブラリごとに覚える（`library.db` の `settings` の `exportDest`）
- 別のライブラリの書き出しを選んだとき（記録の `library` が違う）は、確認してから新しく `<ライブラリ名>/` を作る。
  ライブラリの識別子は初めて書き出すときに作り、`settings` の `libraryId` に入れる

## 2 回目以降：変わったものだけ

`.stockroom-export.json` に、項目ごとに書き出した場所と中身を記録する。

```json
{
  "version": 1,
  "library": "<libraryId>",
  "exportedAt": 1760000000000,
  "items": {
    "<item id>": { "path": "ストック/旅行/金閣寺 (2).jpg", "base": "ストック/旅行/金閣寺.jpg", "hash": "<sha256>", "size": 123, "mtime": 1760000000000 }
  }
}
```

- `base` は連番を付ける前の場所。同じ項目の `base` が変わらなければ、前回の `path`（連番付き）をそのまま使う。書き出すたびに連番が入れ替わらないように
- 書き出し先のファイルが「書き出したときのまま」かは、大きさと更新日時を記録と比べて見る（合わないときだけハッシュを取る）

| 項目の状態 | 書き出し先のファイル | すること |
|---|---|---|
| 記録が無い（新しい） | — | 書く |
| 場所も中身も記録と同じ | 書き出したときのまま | 何もしない |
| | 無い・変えられている | 書く（変えられていれば連番で別に書き、元は触らない） |
| 場所が変わった（アプリで移動・名前の変更） | 書き出したときのまま | 新しい場所へ移す（コピーし直さない） |
| | 変えられている | 新しい場所へ書き、元は触らない |
| 中身が変わった（テキストの編集） | 書き出したときのまま | 上書きする |
| | 変えられている | 連番で別に書き、元は触らない |
| ライブラリに無い（完全に削除・ゴミ箱） | 書き出したときのまま | 既定では残す。オプションがオンなら OS のゴミ箱へ入れる（`trash` クレートを足す） |
| | 変えられている | 残す |

- 記録に無いファイル（利用者が自分で置いたもの）には触らない
- 移した結果、空になったフォルダは消す（記録にある場所の中だけ）
- 記録は最後に書く（`.tmp` に書いて名前を変える）。途中で止めたり失敗したりしたときも、そこまでに書いたものは記録する

## stockroom.csv

1 行 1 項目。毎回すべて書き直す。Excel でそのまま開けるように UTF-8・BOM 付き（docs/TEXT.md の CSV の新規作成と同じ）。

| 列 | 中身 |
|---|---|
| パス | 書き出し先（`<ライブラリ名>/`）からの場所 |
| 名前 | アプリでの名前 |
| 種類 | 画像・ファイル・テキスト・フォント |
| フォルダ | `旅行/2025/京都`（未分類は空） |
| タグ | `, ` 区切り |
| 評価 | 0〜5 |
| お気に入り | `1` / 空 |
| メモ | 改行もそのまま（CSV の引用） |
| 取り込み元 URL | `source_url` |
| 追加日 | `2025-10-17 14:03`（ローカル時刻） |
| 幅・高さ | 画像だけ |
| 容量 | バイト |
| SHA-256 | 中身のハッシュ |

## ダイアログ

今の書き出しダイアログ（`ExportDialog.tsx`）に、`ListSource` の `{ kind: "library" }` を足して使う。

```
ライブラリ全体を書き出し
  対象：1,234 件（ストック 1,100・フォント 134）。ファイルはそのままの形式でコピーします

  ☑ タグ・評価・メモの一覧（stockroom.csv）も書き出す
  ☐ ライブラリから無くなったファイルを書き出し先からも消す
      書き出したときのままのファイルだけを、ゴミ箱に入れます

  書き出し先：[ ~/Backup/MyPictures ]  [選ぶ…]
    前回の書き出し（10/12 14:03）を更新します     ← 記録があるとき
                                            [キャンセル] [書き出し]
```

- 進み具合を出し、キャンセルできる（数 GB になりうる）。別のライブラリへのコピーと同じ形
- 終わったら「新しく 12 件・移動 3 件・更新 1 件・そのまま 1,218 件」と出す。書き出し先で変えられていて触らなかったものがあれば、その件数も
- フォルダの書き出し（今のもの）は変えない。差分の書き出しは、まずライブラリ全体だけで使う

## 実装

- Rust：`src-tauri/src/export.rs` を作り、`commands.rs` の `export_items`・`export_dir`・`safe_name`・`export_target` を移す。
  ライブラリ全体の書き出しは Rust 側で DB からフォルダの場所を組み立てる（フロントから `subdirs` を渡さない）。モードの表示名だけフロントから渡す
- 計画（何を書く・移す・消す）を作る関数と、実際に書く関数を分け、計画の方を記録と書き出し先の状態の組み合わせでテストする
- コマンドはコマンド表（`commands.ts`）に `library.export` を足し、メニュー（docs/MENUS.md）と設定の「概要」（docs/SETTINGS.md）から呼ぶ
- `api.ts` のラッパとモック（`src/dev/mockBackend.ts`）を同じ PR で足す

### 実装の順番

1. ~~ライブラリの中のファイルの場所を `library.rs` にまとめる~~（済み。`item_dir` / `stored_file` / `store_file` / `remove_item_dir`）
2. `export.rs` への移動と、ライブラリ全体の書き出し（1 回目だけ。記録は書く）
3. 差分（記録との比較、移動、上書き、消す）
4. `stockroom.csv`

## 採らなかった案

- **フォルダ構成どおりに保存する**（`<ライブラリ>/ストック/旅行/金閣寺.jpg`）：アプリでフォルダの名前を変える・移す・消す・取り消すたびにディスクの大量の移動になり、
  途中の失敗や同期サービスとの相性が悪い。ディスクで見られると Finder で動かしたくなり、DB とずれる。Windows で使えない文字、大文字と小文字だけ違う名前、
  モードごとの同じ名前のフォルダ、同じ名前のファイルの扱いも要る
- **元の場所のまま参照する**（ファイルはコピーせず、タグなどだけを重ねる）：「フォルダごとコピーすれば完結する」前提が崩れ、
  移動・削除・外での書き換えへの追従（再スキャン、ハッシュでのつなぎ直し、見つからない表示、監視）と、asset protocol の許可範囲の拡大が要る。
  Finder でファイルを管理したい使い方になったら考え直す
