# Image Library

Eagle 風のローカル画像管理アプリ。画像をライブラリにコピーして、サムネイル一覧・フォルダ分け・タグ付け・検索で整理する。
編集機能や AI 機能は持たない、軽量なデスクトップアプリ（Tauri 2 / Mac・Windows）。

## 機能

- **インポート**：ウィンドウへのドラッグ&ドロップ、「追加」ボタン、クリップボードから貼り付け（⌘V / Ctrl+V）
  - フォルダを取り込むと **フォルダ構造をそのまま再現**（同名フォルダは再利用）
  - サイドバーのフォルダに直接ドロップすると、そのフォルダへ入る
  - 同じ画像（SHA-256 一致）は重複としてスキップ。ゴミ箱にあるものは復元される（すでに別フォルダにある画像は移動しない）
  - 対応形式：JPEG / PNG / GIF / WebP / BMP / TIFF / SVG / HEIC・HEIF / AVIF、フォント（TTF / OTF / WOFF / WOFF2 / TTC / OTC）、ファイル（PDF / Word・Excel・PowerPoint（doc・docx / xls・xlsx / ppt・pptx）/ Pages・Numbers・Keynote）
    - HEIC・AVIF は OS のデコーダで読む（macOS は標準対応。Windows は Microsoft Store の「HEIF 画像拡張機能」「AV1 Video Extension」が必要）
    - HEIC・TIFF は表示用に JPEG のコピーを `previews/` に作る（Windows の WebView が表示できないため）
- **ブラウザから保存**（Chrome / Edge の拡張機能）：Web ページの画像をライブラリへ。保存した画像には元のページの URL が付き、詳細パネルから開ける
  - 画像を右クリック →「Image Library に保存」、Alt（Mac は Option）+右クリックですぐ保存
  - 「このページの画像を一覧して保存…」：ページ内の画像（srcset の大きい版、画像へのリンク、CSS の背景も）を大きさ・形式で絞り込んでまとめて保存
  - 「スクリーンショットを保存」：いまブラウザに見えている範囲を画像にして保存
  - 保存先のフォルダと付けるタグは拡張機能のアイコンから選ぶ
  - 使い始めるには：ライブラリ名のメニュー →「ブラウザ拡張と連携…」でオンにし、「拡張機能のフォルダを用意して表示」→ Chrome の `chrome://extensions` で「デベロッパー モード」をオン →「パッケージ化されていない拡張機能を読み込む」でそのフォルダを選ぶ（このフォルダから入れればそのまま接続される）
  - 別の場所から入れた拡張機能（別のパソコンからコピーしたもの、開発中の `extension/` など）は、拡張機能のアイコン →「アプリと接続」。アプリに確認が出るので、両方に出る 4 桁の番号が同じなら「許可する」
  - アプリは起動中だけ `127.0.0.1:41620` で受け付ける（このパソコンの中の、接続を許可した拡張機能だけ。Web ページからの接続は拒否）。「すべての拡張機能との接続を解除…」で許可を取り消せる。画像は拡張機能がブラウザの Cookie・プロキシ設定のままダウンロードして渡す
- **画像・フォント・ファイルのモード**：サイドバー上部の切替（⌘1 / ⌘2 / ⌘3）で、画像だけ／フォントだけ／ファイルだけを表示する。一覧・件数・フォルダやタグの件数・スマートフォルダは、いま表示しているモードのものになる
  - レイアウト・グループ分けはモードごとに覚える（画像は標準、フォントは見本、ファイルはグリッドが初期値）
  - スマートフォルダは作ったモードに属する（モード分け前に作ったものは両方に出る）
- **一覧**：サムネイルサイズ変更、範囲ドラッグ選択、仮想スクロール
  - ツールバーの 2 段目の右側で、並び順・グループ分け・レイアウト・表示（サムネイルの大きさ、下に出す情報）を切り替える
  - レイアウト（画像）：標準（行の高さをそろえ、縦横比のまま並べる）／Pinterest風（列の幅をそろえ、縦に詰める）はツールバーのボタンで、グリッド・リストは表示メニュー（スライダーのアイコン）から切り替える
    - グリッド：縦に長いスクリーンショットや横長のパノラマが混ざっていても同じ大きさの枠に収まる
    - リスト：1 行ずつ詳しく表示
  - レイアウト（フォント）：見本／リストがツールバーのボタン、グリッドは表示メニュー
    - 見本：フォントを 1 行ずつ大きく並べて見比べる。上の欄に入力した文字が全部のフォントに反映され（空欄なら各フォントの見本）、大きさは 12〜160px（⌘+ / ⌘-）。フォントに無い文字は赤い点線で示す
    - リスト：そのフォントで描いた見本の文字とファミリー名・スタイルを表示（画面に見えている行のフォントだけを読み込む）
  - サムネイルの下に出す情報（名前・画像サイズ・評価・形式と容量）を切り替え
  - **グループ分け**：評価（★5〜未評価）／タグ（複数タグのものは各タグに表示）／フォルダ（「すべて」やサブフォルダ表示で便利）／ファミリー（フォントのみ。同じフォントの太さ違いを細い順にまとめる）。区切りの見出しをクリックするとその区切りをまとめて選択
  - 並び替え：追加日・名前・ファイルサイズ・画像サイズ・評価・**手動**（フォルダ内でドラッグして並べ替え）
  - 「サブフォルダの内容も表示」でフォルダ配下をまとめて表示
- **整理**：入れ子フォルダ（1 枚は 1 つのフォルダにだけ入る。複数の分類にはタグを使う）、タグ（補完付き）、メモ、**★評価（0〜5）**
  - **お気に入り**（F、サムネイルのハート）とは別に **ピン留め**（P）があり、ピン留めした画像はどの一覧でも先頭に表示される。サイドバーの「お気に入り」「ピン留め」でまとめて見られる
  - フォルダ・スマートフォルダ・タグに **色** を付けられる（サイドバーで右クリック → 色の行から選ぶ。9 色）
  - フォルダの順番は自由に変えられる（行の上端・下端へドロップ、⌘[ / ⌘]）。右クリックで名前順に戻す
  - タグのコピー／貼り付け（⌘⇧C / ⌘⇧V）
  - 画像をサイドバーのフォルダへドラッグ、または **フォルダ移動ダイアログ**（⌘⇧J：検索・新規作成）
  - Shift+D で直前に使ったフォルダへ移動、「選択から新規フォルダ」
- **検索・絞り込み**：名前・メモ・タグ名・フォントのファミリー名を検索（`-語` で除外、`A OR B` / `A || B`、`( )`、`"語句"`）、タグ・★評価で絞り込み
  - 絞り込みバー（⌘⇧F）：形式・縦長／横長／正方形・画像サイズ（px）・追加日・容量
  - 絞り込み中は一覧の上に条件が一覧表示され、条件ごとの ✕ と「すべて解除」で外せる（ビューを切り替えると自動で解除）
  - **スマートフォルダ**：今の条件（検索・タグ・評価・絞り込み）を保存すると、当てはまる画像が自動で集まる。右クリック →「条件を編集」で変更
- **ビューア**：拡大縮小（⌘+ / ⌘- / ⌥・Ctrl+ホイール / ピンチ）、実寸 ⌘0、全体 ⌘9、ドラッグでスクロール
  - 詳細パネル（I）で名前・サイズ・タグ・フォルダ・メモを確認し、評価・お気に入り・ピン留めを変更。下部のサムネイル（T）で前後の画像へ移動。1〜5 / F / P のキーも一覧と同じ
- **重複の整理**：サイドバーの「重複の候補」で、見た目が似ている画像をグループにして並べる（類似ハッシュ。完全一致は取り込み時に除外済み）
  - 「似ている度合い」を 3 段階で切り替え：**ほぼ同じ**（リサイズ・再保存程度）／**似ている**（標準）／**やや似ている**（無関係な画像も混ざる）
  - 各画像に「残す」「ゴミ箱へ」を表示し、「これを残す」で残す 1 枚を選べる（初期値は最高画質）
  - 「整理…」を押すと確認ダイアログで、残す／捨てる画像と、残す 1 枚へ引き継ぐタグ・評価・フォルダ（未分類のときだけ）を事前に確認できる。実行後は元に戻せる（引き継いだタグ・評価は残る）
  - グループ見出しの「重複ではない」で候補から外せる。ツールバーの「すべて解除」で戻せる
- **フォントの絞り込み**：フォントモードではサイドバーに **言語**（日本語・欧文・中国語・韓国語・その他）と **書体**（明朝・セリフ／ゴシック・サンセリフ／丸ゴシック／筆・手書き／デザイン／等幅／未分類）が出て、今のフォルダやタグの絞り込みと組み合わせて絞り込める（⌘・Shift+クリックで複数選択）。スマートフォルダの条件にもなる
  - 言語は含まれる文字から判定。書体はフォント名（「明朝」「Gothic」「Rounded」など）とフォント内の分類情報から自動で判定し、分からないものは「未分類」。詳細パネルの「書体」で選び直せる（複数のフォントを選んでまとめて設定も可）
- **ファイル**（PDF・オフィス文書）：取り込んで、タグ・フォルダ・評価・メモで整理する。編集や中身の検索はしない
  - サムネイルは 1 ページ目。macOS は Quick Look、Windows は PDF だけ OS の PDF 描画で作る。作れないときはファイルの中に保存されたプレビュー（Pages / Numbers / Keynote、サムネイル付きで保存した Office 文書）、それも無ければ種類のカード（「XLSX」など）
  - ビューアでは PDF をそのまま読める。オフィス文書はサムネイルと「既定のアプリで開く」
  - パッケージ形式（フォルダ）で保存された古い Pages / Numbers / Keynote は取り込めない
- **フォント**：見本（"Aa" と、含まれる文字に合わせて「あア永」か "ABC abc 123"）を描いたサムネイルで一覧に並ぶ
  - ビューアで、入力した文字を好きな大きさで試せる（12〜200px、小さいサイズの見本も表示）。フォントに無い文字は赤い点線付きで示す（システムのフォントで代わりに表示されるため）。含まれる文字の一覧（先頭 3000 字まで）
  - ファミリー名でも検索できる。グループ分けの「ファミリー」で、太さごとに別ファイルのフォント（Light / Regular / Bold …）をまとめて見られる。ファミリー名に太さが入ったフォント（「MOBO-Bold」「〜ボールド」）も、太さを取り除いてまとめる
  - 詳細パネルにファミリー・スタイルと太さ・文字数・製作者・版。可変フォントは軸（太さ 100〜900 など）と名前付きスタイルの数、TTC / OTC は中のフォントの一覧
  - TTC / OTC は 1 ファイル = 1 件。ビューアで中のフォント（W3 / W6 など）を切り替えて見る
  - 画素のサイズは無いので、縦長／横長・画像サイズの絞り込みと重複の候補には出ない。回転もできない
- **回転・反転**：右クリック、⌘⇧L / ⌘⇧R、ビューアのボタンで、90° 回転・左右反転・上下反転・元の向きに戻す
  - 元のファイルは書き換えない（向きだけを記録して、サムネイルとビューアに反映）。⌘C・ドラッグ・書き出しは今のところ元の向きのまま
- **持ち出し**：⌘C でクリップボードへ（ファイル＋画像データ）、ウィンドウの外へドラッグして他のアプリへ、既定のアプリで開く、フォルダへ書き出し
- **作業台**：まとめて出力・書き出しの前に、画像を一時的に集めておく場所（サイドバーの「作業台」）
  - 画像を選んで B キー、右クリック →「作業台に追加」、詳細パネルのボタン、サイドバーの「作業台」へドラッグで追加。もう一度 B で外す
  - 作業台を開くと「手動」の並び（入れた順）になり、ドラッグで並べ替えられる（離れると元の並び順に戻る）。この並びではピン留めも先頭に出さない
  - ツールバーの「まとめて出力…」「空にする」、2 段目の「書き出し…」。選択中ならその画像だけ、選択なしなら作業台のすべてが対象
  - 「空にする」は作業台から外すだけで、画像は消えない（元に戻す可）。ライブラリごとに保存され、アプリを閉じても残る
- **まとめて出力**：選んだ画像を番号付きで 1 枚の画像（PNG / JPEG）か 1 つの HTML にまとめる。「この中でどれがいい？」と聞きたいときに、1 ファイルで渡せる
  - 右クリック →「まとめて出力…」、または作業台から。並びは一覧の順
  - タイトル、番号（1, 2, 3 / A, B, C / なし）、画像の下の名前・サイズ・形式・容量、列の数（自動は 16:10 くらいになる列数）、画像の幅（1200〜3600px）、背景（白／黒）を選べ、プレビューで確認できる
  - 形の違う画像が混ざっても、同じ大きさの枠に全体が収まる（回転・反転を反映。フォントは見本の画像）
  - 「画像をコピー」でクリップボードへ（チャットやメールに貼り付け）、「保存…」でファイルに
  - HTML は画像を中に入れた 1 ファイル。画面の幅に合わせて並び、クリックで拡大（← → で前後）
- **ゴミ箱**：⌘⌫ / Delete で移動（元に戻す可）、復元・完全削除

## ライブラリの構造

ライブラリは 1 つのフォルダで完結しているので、フォルダごとコピーすればバックアップ・別 PC への移動ができる。

```
MyPictures.library/
  library.db                 # SQLite（フォルダ・タグ・メモなど）
  images/<id>/<元のファイル名>  # 取り込んだ画像のコピー
  thumbs/<id>.jpg|png        # 長辺 512px のサムネイル（透過画像は PNG）
  thumbs/<id>_o<反転><回転>.jpg|png  # 回転・反転した画像のサムネイル（元のサムネイルも残す）
  previews/<id>.jpg          # HEIC・TIFF の表示用 JPEG（長辺 4096px まで）
```

### バックアップ

- **アプリを終了してから** `.library` フォルダごとコピーする。起動中は SQLite の作業ファイル（`library.db-wal` / `-shm`）に未反映の変更があるため、途中の状態を写してしまうことがある
- Time Machine はそのままで良い（APFS のスナップショットで一貫した状態が保存される）
- 取り込んだ画像のファイルは後から変わらないので、差分コピー（`rsync -a` / `robocopy /MIR` など）なら 2 回目以降は新しい画像だけが写る
- iCloud Drive・Dropbox・OneDrive などの**同期フォルダの中で直接使わない**。書き込み中に同期されて DB が壊れたり、2 台で同時に開いて競合したりする。同期先にはバックアップのコピーを置く
- 戻すとき：コピーしたフォルダを置き、「既存のライブラリを開く」で選ぶ

最後に開いたライブラリのパスはアプリ設定（macOS: `~/Library/Application Support/com.local.imagelibrary/settings.json`）に保存される。

## インストール

[Releases](https://github.com/2204601/image-library/releases) から入手する。署名（Apple Developer ID / Windows コード署名）なしのビルドなので、**初回インストール時だけ**警告が出る。

- **macOS（Apple Silicon 専用）**：`.dmg` を開いて「アプリケーション」へコピー → 起動すると「開発元を検証できない」と出るので「完了」→ **システム設定 › プライバシーとセキュリティ** の下にある「このまま開く」を押す。
  ターミナルで `xattr -dr com.apple.quarantine "/Applications/Image Library.app"` を実行しても良い。
- **Windows**：`-setup.exe` を実行 → SmartScreen が出たら「詳細情報」→「実行」。

### アップデート

2 回目以降はアプリ内で更新する。起動から数秒後に新しいバージョンを確認し、あればダイアログで知らせる（「更新して再起動」で適用）。手動で確認するにはサイドバー上部のライブラリ名 →「アップデートを確認…」。

会社のネットワークなどでプロキシが必要な場合は、OS のプロキシ設定（自動プロキシ設定の PAC を含む）をそのまま使う（`src-tauri/src/proxy.rs`）。

アプリ自身が書き出したファイルには macOS の quarantine 属性が付かないので、この経路で更新すると Gatekeeper / SmartScreen の警告は出ない。更新ファイルは Tauri Updater の鍵（minisign）で署名されていて、アプリ側の公開鍵と一致しないものは適用されない。

## 開発

前提：Node.js 22+、Rust（stable）、[Tauri の前提環境](https://tauri.app/start/prerequisites/)

```bash
npm install
npm run tauri dev      # アプリを起動
npm test               # Rust のユニットテスト + 型チェック
npm run tauri build    # 配布用ビルド（.dmg / .msi）
```

- `npm run dev` でブラウザから開くと、Rust 側の代わりにインメモリのモック（`src/dev/mockBackend.ts`）で動く。UI だけ触りたいとき用（インポートは不可）。
- 画像・フォント・ファイルの分け方（モード）と、共通基盤と種類ごとのコードの境界は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) にまとめてある。
- テスト用ライブラリの生成：`npm run seed -- /path/to/Test.library 10000`
  （1 万枚の取り込み 約 6 秒、検索+並び替えクエリ 約 6ms ／ Apple Silicon・release ビルド）
- ブラウザ拡張の開発：`cargo run --manifest-path src-tauri/Cargo.toml --example webserver -- /path/to/Test.library` でアプリなしに受付サーバーを起動し（`extension/config.json` に接続キーを書く。「アプリと接続」は確認なしで許可する）、Chrome で `extension/` を読み込む。アプリが起動中でポートが使われているときは `-- <library> <拡張のフォルダ> 41699` のように別のポートを指定する（`config.json` にそのポートが書かれる）。拡張機能のファイルを変えたら `chrome://extensions` で再読み込み

### リリース

`v*` タグを push すると GitHub Actions で macOS（Apple Silicon 専用）と Windows のインストーラがビルドされ、そのタグのリリースが下書きで作られてインストーラが添付される（内容を確認して Publish）。手動実行（workflow_dispatch）の場合は Actions の Artifacts にだけ出る。

手順：`package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml` のバージョンを上げる → `chore: vX.Y.Z` でコミット → `git tag vX.Y.Z && git push --tags` → ビルド完了後に下書きリリースを **Publish**。

アプリ内アップデートは `releases/latest/download/latest.json` を見るので、**Publish するまで配信されない**（下書きのうちは旧バージョンのまま）。リリースには次が添付される。

- `Image Library_X.Y.Z_aarch64.dmg` / `-setup.exe`：初回インストール用
- `Image Library.app.tar.gz` と `.sig`、`-setup.exe` の `.sig`、`latest.json`：アプリ内アップデート用（tauri-action が生成）

更新ファイルの署名鍵は GitHub Actions の Secrets に置く（`TAURI_SIGNING_PRIVATE_KEY`：秘密鍵ファイルの中身、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：パスワード、未設定なら空）。対応する公開鍵は `tauri.conf.json` の `plugins.updater.pubkey`。**秘密鍵を失うと配布済みのアプリに更新を届けられなくなる**ので、必ずバックアップを取る。鍵の作り直しは `npx tauri signer generate -w ~/.tauri/image-library.key`。

ローカルで配布用ビルドをするときも署名鍵が要る（`createUpdaterArtifacts` が有効なため）。

```bash
TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/image-library.key)" npm run tauri build
```
